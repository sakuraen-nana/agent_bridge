## Why

两处默认体验缺口：

- **窗口形态**：主窗口当前以 1000×720 的横向尺寸启动。本应用实际使用形态是常驻侧栏式的控制面板，1:2 竖向窄窗更贴合使用（与桌面一侧并排），也避免无谓的横向占位。
- **短名默认值**：首次使用时短名为空，发现与配对界面里本机显示「未命名」，须用户手动起名。以本机设备名（主机名）作为默认短名，开箱即有可辨识身份；原规格曾明确「MUST NOT 自动代填（如主机名）」，本次按用户需求反转该语义。

## What Changes

- **启动窗口尺寸**：主窗口启动时以宽:高 = 1:2 的竖向尺寸显示——默认 480×960；屏幕可用高度放不下默认尺寸时等比缩小（仍保持 1:2）以完整显示；最小尺寸同步调整为 360×720（同为 1:2）。比例仅在启动时应用，运行中不锁定，用户可自由调整窗口大小。
- **短名默认初始化**：应用启动时若本机短名为空（从未设置、已清空或配置中为空值），自动以本机设备名（Linux 主机名 / Windows 计算机名）初始化并持久化；设备名不满足短名规则（去首尾空白后 1–32 字符、无空白或控制字符）时保持为空，MUST NOT 截断或替换字符；已有非空短名 MUST NOT 被覆盖。清空仅在当次运行内生效，下次启动按上述规则自动填回（用户确认的语义）。
- **规格修订**：`agent-bridge-app` 的「本机默认短名」要求删除「MUST NOT 自动代填」表述并改为上述初始化语义（含「清空短名」场景改写）；新增「启动窗口尺寸」要求。

**BREAKING**：无（行为增强；不涉及协议、CLI 输出与配置文件结构）。

## Impact

- `app/lib/main.dart`：启动窗口选项（尺寸/最小尺寸）；尺寸计算提取为可单测的纯函数；`runApp` 前调用一次短名启动补全
- `app/pubspec.yaml`：新增 `screen_retriever` 直接依赖（现为传递依赖；用于读取屏幕可用区域）
- `app/rust/src/config.rs`：新增补全函数（短名为空时以设备名初始化并持久化）
- `app/rust/src/api/device.rs`：新增桥接函数 `ensure_default_short_name`（**不放入 `app_init`**——清空按钮为刷新快照也调 `app_init`，放入会使清空被当场填回）；设备名取值复用 `sysinfo`；重跑 `flutter_rust_bridge_codegen generate` 并提交生成物
- `app/lib/src/bridge_service.dart`：桥接抽象与真实实现新增对应方法（widget 测试假实现同步补齐）
- 测试：Rust config 集成测试新增用例（初始化/不覆盖/非法设备名/清空后再次调用填回）；Dart 尺寸计算单测；集成测试在 Linux（Xvfb）实跑断言启动窗口比例与补全行为
- Windows 真机的窗口表现与短名初始化列入「待用户验收清单」
- 版本推进：归档前 `0.5.0` → `0.6.0`
