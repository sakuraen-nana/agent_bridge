## Why

被控端目前把「启动时的所在目录」当作工作目录：要固定到某个项目目录，只能先 `cd` 过去再启动，且没有任何保护——目录写错或权限不足时服务照样起来，直到某条 exec / download 在运行期以难懂的方式失败。另一方面，控制台留痕只把「响应」当一等公民：download 只显示解析后的绝对路径、看不到调用方传入的原始 `path`，hello 只显示响应，认证通过却被 400/404 拒绝的请求有的显示截断预览、有的什么都不显示。远程排障时看不到调用方「到底发了什么」，只能靠猜。

## What Changes

- 新增启动参数 `--workdir <路径>`：指定被控端服务器的默认工作目录，取代「启动时的 cwd」。该目录成为 exec 缺省 cwd 与相对 cwd 的基准、download 相对路径的基准、hello 响应 `cwd` 字段与启动横幅「工作目录」行的取值
- 目录无效即拒绝启动：不存在 / 不是目录 / 存在但不可读取，均输出明确错误并以非零退出码退出。不传 `--workdir` 时行为与现状完全一致
- `run.py` 把该参数转发给程序主体（入口仍保持自定位、可在任意工作目录下调用）
- 留痕排版改为分节式：通过 token 认证的请求，请求参数与响应内容分小节完整显示（如 `▸ 请求参数` / `▸ 实时输出` / `▸ 响应`）
- 补全参数显示缺口：download 显示调用方传入的原始 `path` 与解析后的绝对路径；hello 响应按字段完整显示；认证通过但被 400/404 拒绝的请求统一完整显示请求参数
- 显示完整性设高上限（64KB），超出部分显式标注「已省略 N 字节」——不假装完整
- 未通过 token 认证的请求**维持现状**：仅 token 状态与截断预览，不解析、不执行
- 同步修订主规格 `openspec/specs/agent-bridge/spec.md` 的对应 requirement

**BREAKING**：无。`--workdir` 不传即保持现有行为；留痕形态变化只影响人读的控制台输出，协议与退出码约定不变。

## Capabilities

### New Capabilities

（无——本次只修改既有能力的行为契约）

### Modified Capabilities

- `agent-bridge`：
  - 「服务启动与 token 生命周期」——新增 `--workdir` 启动参数、无效目录拒绝启动的行为与退出码
  - 「请求留痕与本地回显」——扩展为「认证通过的请求，参数与响应均完整分节显示」；认证失败请求维持截断预览
  - 「Hello 问候 API」/「Exec 命令执行 API」/「Download 文件下载 API」——工作目录基准由「启动时的 cwd」改为「启动参数指定（缺省仍为启动时的 cwd）」
  - 「统一 Python 入口」——入口转发 `--workdir` 且保持自定位与任意工作目录可用

## Impact

- 受影响代码：`src/agent_bridge/server.py`（启动参数解析、工作目录取值、留痕排版与完整性上限）、`run.py`（参数转发）、`tests/`（新增用例）、`README.md`（启动方法与参数说明）
- 协议与退出码：三类 API 的请求/响应形态不变；新增的是启动命令行参数与「无效目录」这一条退出路径
- 兼容性：不传 `--workdir` 时行为不变；控制台留痕属人读输出，不影响任何机器可读约定（入口 stdout 与直调主体逐字节一致这一约定继续成立）
- 依赖：无新增，仍仅标准库；Linux 与 Windows 行为一致
