## Why

路线图第 3/5 步。新应用已具备完整通道能力（变更 ②），但四处「装上即用」的运维缺口尚在：① **权限**——用户已确认「启动即请求管理员/root 并全程以最高权限运行」（Windows UAC / Linux pkexec），当前应用不提权，防火墙放行也无从谈起；② **防火墙**——被控机防火墙拦截 37777 会让通道静默不可达，需自动检测并放行；③ **常驻形态**——被控端要求「关窗不掉线、开机自启动」，当前关窗即退出；④ **凭据分发**——需要「复制本机有效配置（本次会话短期 token）到剪贴板」的一键出口，配合对端手工配置或后续图形化配对。

## What Changes

- **管理员权限**：应用启动即检测并请求管理员/root——Windows 以清单（requireAdministrator）触发 UAC；Linux 图形会话下经 `pkexec` 以待提权方式重启应用并退出本实例；已是 root/管理员直接继续。提权被取消或不可得（无图形会话、无 pkexec）时**不退出**：以显著横幅告知「受限模式」（防火墙放行步骤标记为未执行），其余功能可用
- **数据目录按调用者解析**：提权重启时显式传递调用者的 `XDG_CONFIG_HOME`；`sudo` 启动路径识别 `SUDO_USER`/`PKEXEC_UID` 回落到调用者用户目录——配置与日志不写进 `/root`
- **防火墙自动放行**：服务端启动后检测防火墙并放行**实际服务端口**（TCP）：Linux 探测 ufw → firewalld（命令输出强制 `LC_ALL=C` 解析）；Windows 探测 Defender（netsh）。活跃则**幂等**加入放行规则（已放行则跳过）；无受支持的活跃管理器（如仅裸 nft/iptables）→ 明确报告「未检测到受支持的活跃防火墙，如有自管规则请手动放行 37777/tcp」，不阻断。只增删本工具的规则，MUST NOT 改动其它防火墙配置
- **托盘常驻与开机自启**：关闭窗口默认隐藏到系统托盘（进程与服务端存活）；托盘菜单：显示窗口 / 复制本机配置 / 退出（退出停止服务端）；托盘不可用（如无 StatusNotifier host）→ 降级为关窗即退出并提示。开机自启开关（默认关）：Linux 写 `~/.config/autostart` 的 `.desktop`（含提权启动命令），Windows 写 `HKCU\...\Run`；状态以系统机制现状为准，开关幂等
- **配置片段复制到剪贴板**：界面按钮将 TOML `[[peer]]` 片段（uuid / 短名（未设置则略）/ 局域网地址 / 端口 / **本次会话短期 token**）写入系统剪贴板，可直接粘贴进对端 `config.toml`；地址选择排除容器/虚拟网桥接口并优先私网地址；无可用地址或服务端未运行时报错提示
- **面板扩展**：信息面板新增「管理员权限」「防火墙」状态行（含受限模式与「需手动放行」说明）
- **规格**：`agent-bridge-app` 新增「管理员权限运行」「防火墙自动放行」「托盘常驻与开机自启」「配置片段复制到剪贴板」四组要求；修改「启动信息面板」增补状态行

**BREAKING**：无（新应用既有用户为零；关窗行为在托盘不可用时保持与现状一致）。

## Impact

- Rust：新增 `elevation.rs`（检测与 pkexec 重启）、`firewall.rs`（探测/放行；命令执行走注入点，全分支可单测）、`autostart.rs`；`config.rs` 数据目录解析扩展（SUDO_USER/PKEXEC_UID）；桥接面增快照字段与 `share_payload()`。新依赖 `is_elevated`（或自实现两端检测）
- Flutter：新增 `tray_manager`、`window_manager` 插件（实施时先验证 pub 镜像可得性；不可得则评估最小自实现）；托盘图标资源（生成 32×32 PNG 入库）
- Windows：runner 清单加 `requireAdministrator`（构建产物每次启动弹 UAC——用户在验收清单确认）；防火墙/自启的 Windows 机制走用户验收
- 数据与安全：README 安全声明扩充（全程管理员、自动放行规则、托盘常驻的威胁模型变化）
- 验证：Linux 侧可测——已 root 直通、受限模式（非 root 无图形）、防火墙「检测→跳过/未检出」两路径、自启文件生成与幂等、剪贴板片段经真实剪贴板读回并可直接连通本机、托盘不可用降级；pkexec 弹窗链路与 Windows 全机制列入用户验收
