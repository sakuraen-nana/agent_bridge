## Context

动机与范围见 `proposal.md`；行为契约见本变更的差异规格与归档前的主规格。

实现面的现状（决定了本设计的取舍）：

- `src/agent_bridge/server.py` 以模块级常量 `START_DIR = os.path.abspath(os.getcwd())` 表示工作目录，被 6 处引用：hello 的 `cwd` 字段、exec 缺省 cwd、exec 相对 cwd 基准、download 相对路径基准、启动横幅「工作目录」行
- 入口 `run.py` 的分发已是 `rest = args[1:]` 后交给 `python -m agent_bridge.server`，即**启动参数天然可转发**；但 `server.main()` 目前不接收任何 argv
- 入口文件受「整文件可被 Python 2 解析」约束，只能容纳极薄的逻辑
- 留痕排版集中在 `_open_block` / `_kv` / `_kv_lines` / `_block_close` 四个辅助方法；测试**未**断言排版细节
- 测试夹具 `_support.TestServer` 采用「覆盖模块全局 → 用后还原」模式（`BRIDGE_PORT` / `TOKEN` / `handler.timeout`）

## Goals / Non-Goals

**Goals**

- 被控端可在启动时指定默认工作目录，且目录不可用时**在启动期**失败并给出可读原因
- 控制台留痕对通过认证的请求做到「参数与响应都完整、可分节扫读」，同时对未认证请求守住既有的最小暴露

**Non-Goals**

- 不提供运行期切换工作目录的能力（无对应 HTTP 端点）
- 不改变 exec `cwd` 参数**本身**的语义与校验，只改其缺省基准
- 不把留痕写入文件或任何持久化渠道（仍仅控制台）
- 不调整未认证请求的预览上限（2048 字节）与 token 脱敏规则
- 不新增 `--port` 等其他启动参数（如需要，另立变更）

## Decisions

### D1 参数在被控端主体解析，入口只做原样转发

`server.main(argv)` 内解析；`run.py` 的分发逻辑**不改**（现有 `args[1:]` 转发已满足规格）。

- 理由：入口必须整文件可被 Python 2 解析并保持极薄；服务端参数语义属于服务端，放进入口会让入口为每个新参数长分支，且持续受 Py2 兼容约束掣肘。
- 备选：入口解析并转成绝对路径后下发 —— 否决（同上）。
- 副作用（有意为之）：`python run.py --workdir X`（不带 `server`）不成立，`--workdir` 会被当成未知子命令报错退出。入口分发以第一个位置参数判定，避免与将来的客户端全局选项产生歧义。README 写明正确写法。

### D2 用 argparse 解析

- 标准库、零第三方、3.7+ 可用；不传参数时 `workdir=None`，行为不变。
- 未知参数/缺值由 argparse 报错并以码 2 退出，与入口的用法错误同类。
- 备选：手写解析 —— 否决（易错、无收益）；环境变量指定 —— 否决（不可见、难排障、两平台设置方式不一）。

### D3 目录校验采用「存在 + 是目录 + 可列出」，失败即退

`os.path.isdir(p)` 之后再 `os.listdir(p)` 探测可读性（捕获 `OSError`，含 `PermissionError`）。

- 理由：exec 与 download 的运行期都要读该目录。启动期失败给出的是「指明原因 + 非零码」的清楚信号；运行期失败则是散落在每条命令里的、难以归因的报错。
- 相对路径基准：`--workdir` 的相对路径以**启动时的 cwd** 解释（调用者视角），解析为绝对路径后固定。
- 备选：仅 `isdir` —— 否决（权限不足会延后爆炸）；追加可写性校验 —— 否决（本工具只读该目录，写入由 exec 子进程自行负责，过度校验会误拒合法用例）。
- 已知局限：指向可移动介质或网络盘时，运行期断开不在启动校验覆盖范围内（见 Risks）。

### D4 实现中重命名为模块级 `WORK_DIR`

`START_DIR` → `WORK_DIR`，仍为模块级：导入时取启动 cwd，`main()` 在参数校验通过后覆盖（`global`），与既有 `TOKEN` 的处理方式一致。

- 理由：改名消除「它一定是启动目录」的错误暗示——现在它可能是 `--workdir` 指定的目录；保留模块级则测试夹具可沿用既有的「覆盖全局再还原」模式。
- 备选：挂到 server 实例上逐层传参 —— 否决（当前无实例级配置通道，改动面大且与代码风格不符）。
- 波及：`_support.TestServer` 的保存/还原元组加入 `WORK_DIR`；`tests/test_server.py` 中 3 处 `server.START_DIR` 随之改名。

### D5 无效 `--workdir` 的退出码定为 2

- 既有约定：入口的用法/版本错误 = 2，服务端口占用 = 1。参数无效属「用法错误」类，取 2；错误信息走 stderr。
- 规格只要求「非零码」，此处固定为 2 以便用例断言与用户排障。

### D6 留痕分节排版：保留 `┌ │ └` 骨架，新增小节与对齐

新增 `_section(title)`（打印 `│   ▸ <标题>` 并以空行分隔）与对齐版的字段打印：同一小节内的键名按最长键对齐（`command          = git pull`）。请求行、结尾行与竖线骨架不变。

- 理由：并发请求交错时，竖线是判断「哪几行属于同一请求」的唯一锚点，去掉会显著降低可读性。
- 备选：完全去掉竖线 —— 否决（同上）。

### D7 完整性上限按「块」生效，exec 实时输出流除外

新增 `_emit_block(text, limit)`：单段文本超过 64KB 时按 **UTF-8 字节**截断，截断点回退到字符边界（`decode(..., "ignore")`，避免切碎多字节字符），并在尾部追加「（已省略 N 字节）」。

- 适用对象：请求参数块、响应 JSON 块。
- exec 的实时输出**不适用**：它逐事件转发、本就没有「整块」边界；规格已显式写明，避免实现者顺手加上限而削减既有能力。
- 备选：按字符计数 —— 否决（与「内容多大」的直觉不一致，中文场景偏差尤其明显）。

### D8 未认证路径零语义改动

`_log_rejected` 的逻辑（token 状态 + 2048 字节截断预览 + 不解析不执行）保持不变；仅其行缩进随 D6 对齐，属排版而非行为变化。

### D9 启动横幅标注工作目录来源

横幅「工作目录」行标注该目录的来源：由 `--workdir` 指定，或未指定而取启动时的工作目录。

- 理由：同一台机器上先后或并行跑多个实例、或参数误传时，「这个目录是从哪来的」是排障第一问；标注后无需回翻启动命令即可判定。该行为已写入规格（`服务启动与 token 生命周期`），实现不得省略。
- 备选：不标注，靠调用者自知 —— 否决（用户明确要求标注）。

## Risks / Trade-offs

- [留痕改动破坏既有用例] → 现有用例未断言 `┌│└` 排版，且 `test_entry.py` 的「入口 stdout 与直调主体逐字节一致」在两侧同一实现下仍成立。缓解：实现后全量跑 `python3 -m unittest discover -s tests`。
- [Windows 难以稳定构造「不可访问的目录」] → 用例做平台分支：不存在 / 不是目录两个子情形跨平台执行，「不可访问」仅在 POSIX 以 `chmod 000` 构造并执行，用例内注明原因；Windows 侧的该子情形列入 tasks 的待用户验收清单，不虚标完成。
- [`--workdir` 指向可移动介质或网络盘，运行中断开] → 启动校验无法覆盖运行期变化。记为已知局限，本变更不处理（超出范围）。
- [测试夹具覆盖全局 `WORK_DIR` 造成污染] → 沿用既有「保存 / 还原」模式，测试串行执行，风险与现有 `TOKEN`、`BRIDGE_PORT` 覆盖同级。

## Migration Plan

无部署态迁移：工具为整目录拷贝、无持久状态、无外部依赖。被控机以 `git pull --ff-only` 取新版即可；不带 `--workdir` 的既有启动命令行为不变。回滚同样是取回旧提交，无数据面影响。
