## Context

动机与范围见 `proposal.md`；行为契约见本变更的差异规格与归档前的主规格。

实现面的现状（决定了本设计的取舍）：

- `client.py` 的 `parse_token_doc(text)` 是**唯一**的文档解析入口：按行剥离，跳过空行与 `#` 注释，`key, _, value = line.partition(":")` 后取 `key.strip().lower()` 与 `value.strip()`，直接写入字典——即"按行序后者覆盖前者"由字典赋值天然实现
- 横幅的 `  Token    : <token>` 行因此**已经**被识别（`"Token".lower()` 恰为 `token`）；`  局域网 IP: 1.2.3.4` 的键是「局域网 ip」，无人消费
- 横幅由本仓库的 `build_banner()` 打印，两侧同仓同版本，格式不是外部输入
- `BRIDGE_VERSION` 在 `server.py` 单点定义，出现在 HTTP `Server:` 头、hello 响应、横幅三处

## Goals / Non-Goals

**Goals**

- 把「粘贴横幅」从"看起来抄对了却报未指定 host"变成开箱可用，且不牺牲既有的手工 `token:` / `host:` 写法
- 给版本号一条可机械执行、不依赖记忆的推进规则

**Non-Goals**

- 不从横幅的 curl 调用示例行提取地址（投机性解析，收益不抵复杂度）
- 不解析横幅里的端口（产品端口固定 37777，无解析价值）
- 不支持 IPv6 地址（横幅只列 IPv4）
- 不拆分"工具版本"与"被控端服务版本"（当前只有一处版本源，无拆分动机）
- 不给版本推进规则添加主规格 requirement——它是工程流程约定，不是工具的行为契约

## Decisions

### D1 解析扩展落在同一个 `parse_token_doc`，不另设"横幅解析器"

文档是**混合内容**（粘贴的横幅 + 手写字段），二者必须按行序共享同一套覆盖语义。两个解析器会立刻产生"谁赢"的歧义。

- 备选：先尝试横幅解析、失败再回退 `key: value` —— 否决（无法处理混排，也无法定义覆盖顺序）。

### D2 横幅行通过与 `key: value` 同一路径识别，只加一个键别名

`parse_token_doc` 已经能把 `局域网 IP: …` 拆成键「局域网 ip」与对应值；因此只需一张键别名表（`局域网 ip` → `host`）与一次取值规范化。`Token` 行无需任何改动——现状已命中。

- 理由：改动面最小，且天然继承"后者覆盖前者"。
- 备选：逐行正则匹配横幅特征串 —— 否决（把两种行形态分裂成两套逻辑，正是 D1 要避免的）。

### D3 地址取值用**显式 RFC1918 判别**，不用 `ipaddress.is_private`

在候选地址中优先 `10/8`、`172.16/12`、`192.168/16`，无则取第一个合法地址。

- 实测（本机 Python 3.12.3）：`100.118.197.100`（CGNAT 段，VPN 常用）`is_private=False`，恰好能被跳过；但 `is_private` 同时还把 `127.0.0.1`、`169.254.0.0/16`、`198.18.0.0/15` 等判为私网——那些都不是"该连的局域网地址"。
- 更关键：**`is_private` 的判定集合随 Python 版本演进**（各版本对特殊网段的分类有过调整），而本工具承诺"目标机任意 Python 3.7+ 行为一致"。用它会把版本差异引进来。
- 因此：用 `ipaddress.ip_address()` **仅作格式校验**（严格、标准库），私网判定用手写的显式区间；同一份输入在 3.7+ 上结果必然相同。
- 备选：纯字符串前缀判断（连格式校验也手写）—— 否决（`inet_aton` 之类会接受 `1.2` 这类简写，不如 `ipaddress` 严格）。

### D4 值为空的行不参与覆盖

模板保留 `token:` / `host:` 空字段；若用户把横幅粘在文件**上方**，末尾的空 `token:` 行会按"后者覆盖"把已识别的 token 清空——这是模板与粘贴并存时最容易踩的坑。

规则：`key: value` 行中 `value` 为空者 SHALL NOT 覆盖已有值（忽略该行）。

- 理由：既解决模板交互，也让"留一行空的 `host:` 待填"这种常见写法不再有害。
- 备选：把模板字段区提到文件开头并注明"粘贴到末尾" —— 否决（依赖用户遵守排版约定，脆弱）。
- 备注：该规则已写入差异规格（可观察行为，不是实现细节）。

### D5 该行解析不出任何地址时不产生 host

横幅在未检测到局域网 IP 时打印「（未检测到，请以 ipconfig / ip addr 输出为准）」。若照搬为 host，client 会拿这句中文去连接，报出难以归因的错误。规则：**候选地址为空则该行忽略**，让 `resolve_target` 照常给出"未指定 host：请用 --host 参数…"的清晰提示。

### D6 版本规则落在 `AGENTS.md`，且 bump 发生在**归档**时

- 规则：每个变更归档时把 `BRIDGE_VERSION` 的 minor 加一（缺陷修复类变更加 patch）；归档清单（`AGENTS.md` 开发流程）增加"bump 版本"一项。
- 不预先决定本变更的数字：在途的 `add-workdir-and-rich-trace` 尚未归档，二者谁先归档谁取 `0.2.0`。这样规则不需要"追溯补记"，也不会出现同一批功能被计两次或漏计。
- 版本号仍为 `server.py` 的单一常量，不拆分。
- 主规格不改：`hello` 返回服务版本这一契约不变；"何时推进版本"属工作约定。

### D7 模板：主推粘贴，保留手工字段

模板说明区改为两条并列的填法——① 首选：把被控机控制台输出整段粘贴进来（`Token` 行与「局域网 IP」行都会被识别）；② 手工：填 `token:`，需要时填 `host:` 覆盖。字段区保留 `token:` / `host:` / `updated:` 空行（依 D4 空值不覆盖，与粘贴并存无副作用）。

## Risks / Trade-offs

- [`is_private` 的版本相关性被忽视] → D3 明确改用显式 RFC1918 判别，并在用例中放入 CGNAT 风格地址（`100.x`）验证会被跳过。
- [模板空字段清空粘贴值] → D4 规则 + 用例覆盖（空值行不覆盖已有值）。
- [多私网网卡时仍需人工选择] → 规则只能取其一；覆盖手段是规格已含的 `host:` 手工行（D7 保留该字段的理由之一）。
- [横幅格式未来漂移] → 横幅内容受主规格「服务启动与 token 生命周期」约束，且两侧同仓发布；解析按行形态，格式变化会在测试中立刻暴露。

## Migration Plan

无部署态迁移：既有 `token:` / `host:` 文档一字不改即可继续用；新增的只是对另一种行形态的识别与一条解析细则。回滚为取回旧提交，无数据面影响。
