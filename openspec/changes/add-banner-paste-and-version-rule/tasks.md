# Tasks: add-banner-paste-and-version-rule

> 实施顺序：解析扩展（1）→ 模板与文档（2）→ 版本规则（3）→ 测试（4）→ 实跑（5）→ 收尾（6）。
> 决策依据见 design.md（D1 单解析入口、D2 键别名、D3 显式 RFC1918 判别、D4 空值不覆盖、
> D5 无地址则忽略、D6 版本规则落在 AGENTS.md 且归档时 bump、D7 模板主推粘贴）。
> 文档边界按既有约定：本仓库不记录使用方的机器名、IP 与部署路径，需指代环境处用通用角色。

## 1. 解析扩展（client.py）

- [ ] 1.1 `parse_token_doc` 支持横幅行形态：新增键别名（「局域网 ip」→ `host`），并确认 `Token` 行仍映射为 `token`；既有 `key: value` 解析结果 MUST 不变；验证：粘贴式文档能解析出 token 与 host，既有文档用例全绿
- [ ] 1.2 新增地址取值：在候选地址中优先 RFC1918（`10/8`、`172.16/12`、`192.168/16`），无则取第一个合法地址；候选为空时该行不产生 host；MUST NOT 使用 `ipaddress.is_private`（判定集合随 Python 版本演进，违背「任意 3.7+ 行为一致」）；验证：用例覆盖 CGNAT 风格地址（`100.x`）被跳过、无私网地址时取第一个、无地址行被忽略
- [ ] 1.3 值为空的行不参与覆盖；验证：把模板式空 `token:` / `host:` 行置于粘贴横幅之后，取值仍来自横幅（用例）

## 2. 模板与文档

- [ ] 2.1 重写 `bridge.local.md.example` 的填写说明：主推「直接粘贴被控机控制台输出」，保留 `token:` / `host:` / `updated:` 字段供手填或覆盖 host；安全警示不变；验证：按模板的两种填法各走通一次
- [ ] 2.2 `README.md` 的 token 文档一节同步说明：可直接粘贴横幅、多地址时优先私网、手工 `host:` 行可覆盖；验证：照 README 步骤可复现，守卫 grep（机器名 / IP / 部署路径）零命中

## 3. 版本推进规则

- [ ] 3.1 `AGENTS.md` 写入版本推进规则：每个变更**归档时**把 `BRIDGE_VERSION` 的 minor 加一（缺陷修复类加 patch），并在开发流程的归档条目中加入「bump 版本」一项；规则 MUST NOT 写死具体数字（在途变更与本变更谁先归档谁取 0.2.0）；验证：照规则可执行且无歧义
- [ ] 3.2 复核 `README.md` 与模板是否需提及版本来源（何处定义、何时推进）；验证：需则补齐、不需则记录结论

## 4. 测试

- [ ] 4.1 解析用例组：粘贴横幅（token + host 同时取到）、多地址私网优先（含 CGNAT 风格）、无地址行被忽略、空值不覆盖、手工 `host:` 行覆盖粘贴值、既有 `key: value` 行为回归；验证：用例通过
- [ ] 4.2 客户端端到端用例：工具副本中放入「粘贴式」文档，`hello` 不经 `--host` 即成功；验证：用例通过
