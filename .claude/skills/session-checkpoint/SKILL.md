# /session-checkpoint 会话落盘检查点

用户中途发出本命令 = **在此刻打一个节点**：把当前会话上下文中有价值的事实（进展、决策、缺陷、环境状态、下一步）蒸馏进**项目的长期载体**，然后提交推送。

**验收的最终判据**：若此刻结束会话，下次在同一工作目录启动的全新会话（零上下文），当用户只问"现在是什么情况、现在该干什么"这类无实质信息的问题时，新 agent **仅凭项目文件**就能正确作答——宏观上对项目架构与脉络清晰，细节上对任务详情与进度有准确把控，知道当前处于什么阶段、下一步是什么。

**本技能是写操作**（与"只审计不修复"的纯审查不同）：发现缺口就修复（更新文档），最后必须提交并推送。

## 持久化层级（写到哪里——本技能的核心约束）

项目必须遵循的体系只有两处：**OpenSpec 工作流**（`openspec/`）与 **AGENTS.md**（AI Agent 项目指令）。落盘一律优先进入长期载体：

1. **第一层：OpenSpec 体系（首选）**
   - `openspec/specs/`——能力规格：行为、约束、需求的长期权威
   - `openspec/changes/<变更>/`——活跃变更的 proposal / design / specs delta / tasks（进度与证据）
2. **第二层：项目真实长期文档与代码**
   - README、使用与运维文档、配置文件、代码注释——运行方式、环境前提、操作流程的归属地
3. **第三层（机会性，非必需）：临时协作产物与记忆**
   - 某一次任务中产生的交接文档、会话报告、任务稿、agent 记忆等：**存在则同步更新以保持一致；不存在绝不假定，更不得作为主要落盘目标**
   - 不得为了让本技能"有地方写"而新建临时文档，去承载本应进入前两层的事实

信息收集同样按此层级：**先**读 AGENTS.md 与 `openspec/`，**再**读 README 等真实文档与代码，**最后**才把发现的临时协作产物作为补充线索。

**仓库自足性（硬约束，与层级同等重要）**：仓库文档必须让**只拿到仓库的人**获得完整、准确的项目信息——仓库可能被克隆到任意一台机器上。

- 记忆、编辑历史（`~/.claude/` 下的一切）、本地缓存、`bridge.local.md` 等**仓库外资源只是补充线索**，**不得成为"读全信息"的必要条件**；能被仓库承载的客观事实一律写进仓库
- 确实只存在于本地的环境细节（某台机器的镜像/代理配置、某台机器上模拟器的连法等）：在仓库文档里**说明它的存在、作用与核实方式**，并标注"属本环境点态、换机器需现场核实"——而不是省略不提、也不能只留在记忆里
- 落盘时自问：**把仓库复制到另一台机器（没有本机记忆与缓存），读者还能得到同样的结论吗？**

## 第一性原理（贯穿全程的写作判据）

- **可读性**：结构化、可扫读；分层组织（宏观一段话 → 中观各任务组 → 微观证据），读者可深可浅
- **引导性**：明确"从哪里开始读、读完该做什么"；下一步必须给入口命令与前置条件
- **有效性**：事实可执行、可复验——带提交哈希 / 包名 / 命令 / 退出码 / 文件路径
- **准确性**：只写已发生或已验证的事实；未验证的**显式标注**，不猜、不省略
- **自包含**：新会话没有本次对话上下文——指代一律展开（"它/那个/上次那个"→ 明确名词）
- **机器无关**：不用"本机 / 本设备 / 这台机器"这类**含义随读取位置改变**的指代——仓库拉取到别的机器后，"本机"就成了错的。机器一律用稳定名称（如 `hermes-machine` / `184`），首次出现处给出角色定义；跨机事实要写清**在哪台机器上、经什么通道、操作了哪台机器**（写"在 A 上经 bridge 触发、在 B 的模拟器上执行"，而不是"在本机上测试通过"）
- **单一权威**：每类事实只在一处是长期权威（行为规格 → specs；变更进度与证据 → 该变更 tasks.md；运行方式 → README/代码；项目级约定 → AGENTS.md），别处引用而非复制

## 执行清单（按序）

### 0. 固定节点坐标

记录此刻的点态事实，供未来复核：时间（UTC + 本地）、分支与 HEAD、相关机器/设备/通道状态（如适用）、关键工具链可用性。**每项带时间戳与一句验证方式**，避免未来会话把点态当常态。

### 1. 会话事实盘点（从上下文提取，不读文件）

把「尚未落盘」的事实列成清单，至少覆盖：

- **做了什么**：动作 + 结果 + 证据（提交哈希 / 生成的产物名 / 退出码）
- **发现了什么**：缺陷 / 根因 / 陷阱 / 环境特性（含已修复与未修复）
- **决定了什么**：方向、边界、模式，以及**为什么**（决策理由比结论更易失传）
- **环境状态变化**：配置落位、镜像、凭据轮换、机器角色变化
- **下一步**：优先级列表 + 每项的前置条件与阻塞
- **仍未知 / 未验证的点**：显式列出（宁可标"未知"，不可留空）

### 2. 持久化事实盘点（读，按层级）

- **锚点（必读）**：`AGENTS.md`、`openspec/` 全目录——`config.yaml`（项目上下文）、`specs/`（能力全景）、`changes/`（活跃变更的状态、tasks 勾选与证据、最近更新）
- **长期文档与代码**：README、`docs/`（若存在）、关键配置文件、代码注释中承载的约定
- **补充线索（存在才读）**：当前仓库或环境中实际存在的临时协作产物、会话记录、记忆目录
- 对每处得出：**载体 / 层级 / 最后更新到哪 / 覆盖了什么 / 缺了什么 / 有无过期**

### 3. 缺口与过期对照 + 工件健康

逐条（会话事实 × 归属），归属按层级优先级：

- 已有且准确 → 跳过
- **缺失** → 归入最合适的长期载体，标记"新增"
- **过期 / 矛盾** → 标记"改写"（直接改写，不堆叠；确需保留演进时附一句"演进："注记）
- **归属冲突** → 收敛到单一权威，别处改引用
- 归属决策示例：行为/需求变化 → specs 或变更的 delta spec；实现决策与理由 → design.md；进度与证据 → tasks.md；运行方式/环境前提 → README 或代码注释；项目级工作约定 → AGENTS.md（高门槛，确属长期约定才动）

同时抽查工件健康（原 check-apply-readiness 保留项，折叠为一项）：

```bash
openspec validate --all
git status --short --branch
```

- 变更工件是否齐全、进度勾选是否带证据、声称的提交哈希是否真实存在（`git log` 比对）
- 仓库是否干净、与远端是否同步

### 4. 落盘（写）

按第 3 步的归属更新。每处自问三句：**新会话读到这句知道要做什么吗？有证据支撑吗？不含对话黑话吗？** 并遵守第一性原理六条。

- OpenSpec 变更内的更新遵循 OpenSpec 工件规范（delta spec 用其格式；tasks 勾选必须带证据注释）
- 临时协作产物**若存在**，同步相应条目即可——不扩写、不新增对其的依赖

### 5. 冷启动预检（提交前自查）

假扮全新会话，且**只有标准入口可用**：AGENTS.md → OpenSpec 工作流 → 仓库长期文档与代码。写出以下问题的预期答复草稿，逐句标注来源文件（这一步在提交前做，先修缺口再落盘；提交推送后的**实境验证**见第 7 步）：

1. **"现在是什么情况？"**——项目在做什么、整体走到哪、架构与关键约束、当前阶段
2. **"现在该干什么？"**——下一步优先级、每项为什么、从哪开始（入口命令）、有什么阻塞
3. **细节抽查 3–5 项**——某个已完成任务的证据、某个环境事实、某个约定或红线
4. **换机复核**——假设仓库被克隆到另一台机器（没有本机的记忆、编辑历史与缓存），上面三问还答得对吗？结论还是同一个意思吗？

任何一句**找不到来源** → 回第 4 步补。**若某句的来源只是临时协作产物（第三层）或仓库外资源，说明它本应在前两层有归属——优先补进前两层。**
另外逐句检查**指代是否机器无关**：出现"本机/本设备"且实指某台具体机器时，改成机器名；跨机事实补上"在哪台机器上、经什么通道、操作了哪台机器"。

### 6. 提交与推送

- 按单元提交（沿用仓库既有的提交信息习惯），推送当前开发分支
- 工作区若有**非文档**的未提交改动：不擅自提交或丢弃，列出并征询用户
- **推送完成后检查点即已成立**，随即自动进入第 7 步实境验证

### 7. 子代理实境验证（提交推送后自动执行，勿询问）

自查会被本次上下文污染，唯有真正的全新上下文能检验"文档真的自足"。因此推送完成后**立即自动**启动一个全新子代理，不得跳过：

- **子代理要求**：全新上下文（用 Agent 工具启动一般型子代理，**不得**用继承上下文的 fork 型）；明确要求只读、不修改任何文件
- **提示词模板**（不得泄漏答案、不得指定具体文档名，否则验证失效）：

  ```
  你是一个全新会话，没有任何历史上下文。工作目录：<仓库绝对路径>。
  模拟处境：用户在此目录新开会话（除自动加载的项目根 AGENTS.md 外没有其他上下文），
  只问了你一句话。请**只依据该仓库内的文件**检索后回答——不要读取工作目录之外的
  任何内容（agent 记忆、编辑历史、本地缓存等都不属于项目文件），并给出每条关键
  信息的来源文件：
  ① 现在是什么情况？（项目在做什么、走到哪了、当前阶段）
  ② 现在该干什么？（下一步是什么、为什么、从哪开始）
  ③ 假设这个仓库被克隆到另一台机器上（没有本机的记忆与缓存），
    ① ② 的结论还成立吗？有没有哪一句只有靠仓库外的信息才能得到？
  ```

- **提示词不得泄漏答案、不得指定具体文档名**，否则验证失效。要求子代理只读、不改动任何文件

- **收到报告后由主 agent 对照分析**（对照物：第 1 步会话事实清单 + 第 3 步落盘内容）：
  1. **事实准确性**：有无错误、过时、臆测？（如把已解除的阻塞说成仍阻塞）
  2. **完整性**：当前阶段、下一步、阻塞、关键约束是否都说到？
  3. **来源健康度**：关键结论的来源是否在 ①OpenSpec / ②长期文档与代码？若只来自 ③临时产物 → 缺口
  4. **引导性**：下一步是否有可执行的入口（命令 / 文件指引）？
  5. **仓库自足性**：有无结论只能靠**仓库外资源**得到（agent 记忆、`~/.claude/` 下的编辑历史与缓存、本地未入库文件）？→ 缺口
  6. **机器无关性**：有无"本机/本设备"这类含义随读取位置改变的指代，或"在哪台机器上、经什么通道、操作了哪台机器"没写清？→ 缺口

- **已知假象（勿误判）**：注入到会话上下文里的"项目记忆索引"取自**会话启动时刻的快照**——本会话内对记忆文件的编辑不会反映到已注入的内容里。子代理因此可能引用到过期的索引文案。判定缺口时一律**以仓库文件为准**，不要把注入快照的陈旧当作仓库文档过期
- **结论处理**：有缺口 → 回第 4 步补，补完再次提交推送并重跑验证（或说明为何无需重跑）；通过 → 进入最终报告
- **用户可不等待**：落盘 + 提交推送完成即检查点已成立，实境验证属附加抽检。用户若没时间等待，直接退出会话即可——下一次真实会话本身就是一次冷启动验证，缺失的只是抽检报告

## 输出格式

```
## 会话检查点：<日期 时间>

### 节点坐标
<分支/HEAD、时间、机器与通道状态，各带验证方式>

### 落盘清单
| 文件 | 层级（OpenSpec / 长期文档 / 临时产物） | 更新类型（新增/改写/无变化） | 内容摘要 | 依据 |

### 冷启动预检
| 问题 | 仅凭标准入口能否答对 | 来源文件（或缺口） |

### 提交与推送
| 提交 | 内容 | 推送状态 |

### 子代理实境验证
<子代理报告要点 + 四项判据（事实准确性/完整性/来源健康度/引导性）的逐项结论；
缺口与补漏动作；或"用户未等待验证即退出">

### 仍未落盘 / 未知项
<逐条：内容、原因、建议>
```

## 边界

- **只动文档与记忆，不改代码**（用户明确要求除外）；本技能不修复缺陷，只如实记录缺陷状态
- **不写入敏感字面值**（token、密钥）——只写位置与获取方式
- **点态事实必须带时间戳**——"当前在线/当前有效"类是快照，不是常态
- **不假定任何非 OpenSpec、非 AGENTS.md 的固定文件名文档存在**；不得围绕临时文档组织信息收集与落盘
- **不写入需要仓库外资源才能读懂的表述**：证据与状态一律写成**机器无关的客观事实**（"在 A 上经 bridge 触发、在 B 的模拟器上执行"），"本机"类指代与"详见某记忆条目"类引用都不合格；仓库是唯一必须自足的载体，仓库外的一切只可作补充线索
- 若本次会话几乎无事可落：仍执行第 5 步预检（保证既有文档对新会话自足），允许明确报告"无需更新"
- 第 7 步实境验证由主 agent 自动发起并等待；用户无需任何操作——愿意等则获得抽检报告，不愿意等可直接退出（落盘与推送已使检查点成立）
- 文档数量保持克制：优先更新既有长期载体，避免碎片化新建
